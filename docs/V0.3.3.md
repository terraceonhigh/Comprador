# v0.3.3 plan — polish after the NFS pivot

**Status — 2026-05-09:** scope and design notes for the polish release
following v0.3.2's working ship. None of these items gate use; they're
the rough edges that surfaced during tonight's verification or
immediately after release. Each item names the symptom, the fix, and
the rough cost.

## Items

### 1. ✓ Phone-side changes don't surface in Finder

**Shipped 2026-05-11.** Implemented exactly as the spec below: the
`ObjectMap.populated` field changed from `map[string]bool` to
`map[string]time.Time`, `IsFresh(dirPath)` returns true only when the
last enumeration is younger than `directoryTTL` (2s), and
`EnsurePopulated` uses freshness rather than mere presence as the
gate.

`populateDir` was extended to reconcile against any pre-existing
cached enumeration when refreshing a stale directory: paths from the
old cache that don't appear in the new device enumeration are
removed recursively (via `RemoveRecursive`, which also strips
descendants — necessary because a phone-side rmdir leaves orphan
file entries in the byPath map otherwise, and a subsequent Stat on
one of them would still return a cached hit pointing at a phone
object that no longer exists).

Unit-tested in `bridge/mtp/objectmap_test.go` — runs via
`make bridge-test`. Four cases: basic byPath/byID, TTL transitions
across `directoryTTL`, recursive removal of a directory and its
descendants, and prefix-collision safety (`RemoveRecursive("/foo")`
must not delete `/foobar`).

End-to-end empirical verification (delete a file via ADB, see it
disappear from the NFS mount within ~2s) is the architect's call on
return; can't be done autonomously without restarting the bridge,
which would unmount the active session.

### 2. Strip the `.local` suffix from the Finder sidebar label

**Symptom.** Sidebar shows `XQ-BT52.local` instead of `XQ-BT52`.

**Why.** Mount source is `<DeviceName>.local:/` because Bonjour
hostnames live in the `.local` namespace. Finder displays the source
hostname verbatim.

**Fix options.**

- **A. `NetFSMountURLAsync` with NFS URL** (prefer if it works).
  Apple's NetFS framework supports `nfs://` URLs and may expose a
  volume-name override key. Worth probing
  `kNetFSMountAtMountDirKey` and friends. Migrates the unprivileged
  mount path from `/sbin/mount` to NetFS without re-introducing the
  helper.

- **B. `/etc/hosts` edit, one-time root prompt at install.** Reverses
  tonight's helper-free simplification but only for cosmetic
  hostname rewriting. AppleScript's `do shell script with administrator
  privileges` would handle the prompt.

- **C. Accept it and document.** `.local` is idiomatic on macOS;
  AirDrop / Bonjour-discovered SMB / screen-sharing all show it.

**Cost.** A: zero ongoing cost if NetFS supports the override; one
afternoon of probing. B: ~30 lines of AppleScript bridging. C: zero.
Recommendation: probe A first; fall back to C.

### 3. ✓ Filter `._xattr` / `.AppleDouble` companion files

**Shipped 2026-05-11.** `bridge/nfs/fs.go` `Create` now returns a
`discardingHandle` (in `bridge/nfs/write.go`) for any path whose
basename starts with `._`. The handle accepts writes silently so
Finder sees `NFSStatusOk` for every WRITE+COMMIT on the
AppleDouble companion file, but no bytes ever reach MTP. The
write registry's `commit` already no-ops for unregistered paths
(early-return on `sf == nil`), so no Commit-side change was
needed. Rename was filtered too — an AppleDouble rename would
otherwise fall through to the slow-path MTP copy+delete and fail
"source not found."

Empirical motivation: the 2026-05-11 ECON101 directory copy
produced 270 `._*` files alongside 432 data files (62% of total
phone-side noise), confirmed via ADB-based phone-side md5
verification.

Trade-off accepted (no application transferring photos / videos /
documents to a phone has a use for resource forks).

### 4. ✓ Refresh `FSStat` free-bytes after writes

**Shipped 2026-05-11** as part of the multi-storage PLAN
implementation (commit `5bfd2462`). `Session.RefreshStorages`
calls `OpRefreshStorages` through the session goroutine on every
FSStat invocation, which re-queries `LIBMTP_Get_Storage` and
atomically swaps the cached storage slice under `storagesMu`.

Went straight to "refresh on every call" rather than the TTL'd
cache the original spec proposed, on the reasoning that FSStat is
called infrequently enough that the libmtp re-query is cheap, and
"Finder shows fresh numbers" is the user-visible behavior we want.
If profiling later shows it's expensive, add TTL.

### 5. ✓ Map MTP modification times into NFS responses properly

**Status (2026-05-11): already shipped — item was stale.**

The fix described below was assumed to be needed, but the
empirical test contradicts that. Spot-check on the architect's
Xperia: `ARCHITECTURE.md` (modified 2026-05-08 23:59:45 on the
phone) shows the same mtime via the NFS mount as it does via
`adb shell stat`. The bridge already wires libmtp's
`modificationdate` through correctly:

- [bridge/mtp/binding.go:310](../bridge/mtp/binding.go) captures
  `f.modificationdate` from `LIBMTP_file_t` into `FileMeta.ModTime`.
- [bridge/mtp/session.go:437](../bridge/mtp/session.go)
  propagates it into `ObjectMeta.ModTime` via `time.Unix(e.ModTime, 0)`.

The `time.Now()` use elsewhere is intentional: directory mtimes
get bumped on each child mutation so NFS clients invalidate cached
READDIR (otherwise recursive folder drags stutter), and
newly-committed files reasonably get "now" since they *were* just
written. The pre-existing-file enumeration path — the one V0.3.3
item #5 was targeting — is already correct.

The "23:48 today" symptom in the original V0.3.3 draft probably
came from looking at a directory mtime (which intentionally tracks
recent activity) or a freshly-committed file (which gets `now`
correctly), not from broken mtime preservation. Closing this
without code changes.

### 6. Fast-path rename (no copy when source is in MTP, parent unchanged)

**Symptom.** Slow-path rename does a full MTP copy + delete even when
the source file isn't moving across directories. For a 1 GB file
that's ~1 minute of MTP traffic for what should be metadata-only.

**Fix.** MTP's `SetObjectPropValue` lets you change an object's name
in place without re-uploading. Wire this for the case where source
parent == destination parent. Inter-parent renames still require
copy+delete (MTP has no move op).

**Cost.** ~30 lines (new MTP op + dispatch in fs.Rename's slow path).

### 7. CI pipeline upgrades

Per `docs/BUILDING.md` § "CI pipeline: where it bit us, what to do
about it." Specifically: add `workflow_dispatch` trigger + always-
upload `.dmg` as a workflow artifact (option A) plus the smoke-test
launch step (option B). Together: ~20 lines of YAML, catches the
class of regression that broke v0.3.0.

### Out of v0.3.3 scope

- **Multi-storage devices** (phones with SD cards). Real architectural
  work, separate plan.
- **Upstream the go-nfs `unstable` patch.** Separate from Comprador's
  release cadence; do at willscott's pace.
- **Quick Look hazard mitigation.** Carryover from WebDAV findings;
  needs investigation against the NFS path before scoping.

## Order of attack

If picking up incrementally, suggested order:

1. **#1 (phone-side reflection)** — biggest user-perceived gap, well-
   bounded fix.
2. **#7 (CI smoke-test)** — prevents the next class of v0.3.x-style
   broken-ship.
3. **#3 (xattr filter)** — small, visible improvement on the phone.
4. **#5 (mtime mapping)** — small, makes Finder's date-sort useful.
5. **#4 (FSStat refresh)** — small, removes the "X GB available" lie.
6. **#6 (fast-path rename)** — measurable speedup for in-place renames.
7. **#2 (`.local` suffix)** — investigation-heavy; do last.

None of these depend on each other; pick the one with the most
leverage at the moment.
