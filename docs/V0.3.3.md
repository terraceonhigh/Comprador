# v0.3.3 plan — polish after the NFS pivot

**Status — 2026-05-09:** scope and design notes for the polish release
following v0.3.2's working ship. None of these items gate use; they're
the rough edges that surfaced during tonight's verification or
immediately after release. Each item names the symptom, the fix, and
the rough cost.

## Items

### 1. Phone-side changes don't surface in Finder

**Symptom.** Delete a file via the phone's own Files app while
Comprador is mounted. Finder still shows the file. Touch a file via
the phone's camera roll — same. The bridge's `ObjectMap` only updates
on bridge-initiated ops; phone-side mutations never reach it.

**Why this happens.** NFSv3 has no server-push callback mechanism
(NFSv4 does). The protocol assumes the client polls and the server's
view is authoritative. Our server's "view" is a snapshot taken at
session start plus deltas from bridge-initiated ops.

**Fix.** Add a TTL to `ObjectMap` directory entries. On
`EnsurePopulated` / `ListChildren`, if the cached enumeration is
older than `directoryTTL` (proposed: 2 seconds), force-refresh from
MTP via `OpListDir` before serving the result.

```go
type ObjectMap struct {
    // ... existing fields ...
    populated map[string]time.Time  // path → last enumerate time
}

func (s *Session) EnsurePopulated(path string) {
    s.Objects.mu.RLock()
    last, ok := s.Objects.populated[path]
    s.Objects.mu.RUnlock()
    if !ok || time.Since(last) > directoryTTL {
        s.refreshDir(path)  // OpListDir + objects.Put for new entries,
                            // objects.Remove for entries no longer present
    }
}
```

**Cost.** One MTP enumerate per directory per `directoryTTL` window
under active browsing. MTP enumerate is ~50–200 ms per directory on
the test phone, well within the parent-mtime-bump window we already
accept. Affects only directories Finder is actively viewing; cold
directories don't pay.

**Edge cases.** A directory the user just deleted via the phone is no
longer in MTP — the refresh returns "not found" and the parent's
listing should drop it on next ReadDir. Handle by detecting
`OpListDir` returning a "no such object" error and removing the path
from `ObjectMap` + bumping the parent's mtime.

### 2. Strip the `.local` suffix from the Finder sidebar label

**Symptom.** Sidebar shows `XQ-BT52.local` instead of `XQ-BT52`.

**Why.** Mount source is `<DeviceName>.local:/` because Bonjour
hostnames live in the `.local` namespace. Finder displays the source
hostname verbatim.

**Fix options.**

- **A. `NetFSMountURLAsync` with NFS URL** (prefer if it works).
  Apple's NetFS framework supports `nfs://` URLs and may expose a
  volume-name override key. Worth probing
  `kNetFSMountAtMountDirKey` and friends. Migrates the unprivileged
  mount path from `/sbin/mount` to NetFS without re-introducing the
  helper.

- **B. `/etc/hosts` edit, one-time root prompt at install.** Reverses
  tonight's helper-free simplification but only for cosmetic
  hostname rewriting. AppleScript's `do shell script with administrator
  privileges` would handle the prompt.

- **C. Accept it and document.** `.local` is idiomatic on macOS;
  AirDrop / Bonjour-discovered SMB / screen-sharing all show it.

**Cost.** A: zero ongoing cost if NetFS supports the override; one
afternoon of probing. B: ~30 lines of AppleScript bridging. C: zero.
Recommendation: probe A first; fall back to C.

### 3. Filter `._xattr` / `.AppleDouble` companion files

**Symptom.** macOS Finder writes `._<filename>` companion files
alongside any drag-dropped file (storing extended attributes / Finder
flags). These currently commit to the phone alongside the data files
— the phone's Files app shows two entries for every file.

**Fix.** Reject `CREATE` / `WRITE` / `COMMIT` for paths matching
`/._/`-prefixed basenames, server-side. The bridge returns
`NFSStatusOk` to the client (so Finder doesn't surface an error) but
doesn't actually stage or commit anything.

**Trade-off.** Some applications rely on AppleDouble files for things
like resource forks. None of the file types most users transfer to a
phone (photos, videos, documents) need them. Accepting the loss is
the right call for a phone target.

**Cost.** ~10 lines in `bridge/nfs/fs.go` `Create` and the staging
registry's `register`.

### 4. Refresh `FSStat` free-bytes after writes

**Symptom.** Finder's "X GB available" string is stuck at the value
the bridge captured at session start. After uploading 1 GB to the
phone, Finder still shows the old number.

**Fix.** `mtpNFSHandler.FSStat` currently returns
`session.FreeBytes()` which itself returns a cached value from
session init. Wire `FreeBytes` to optionally re-query MTP storage
info via a TTL'd cache (10 s or so — FSStat is called frequently).

**Cost.** ~20 lines, plus a `MTPRequest{Op: OpGetStorageInfo}` (which
needs a binding into libmtp's `LIBMTP_Get_Storage` — small).

### 5. Map MTP modification times into NFS responses properly

**Symptom.** Files on the mount show modification times like
"23:48 today" regardless of when the file was actually modified on
the phone. macOS Finder's "Sort by Date Modified" is useless.

**Fix.** libmtp's `LIBMTP_file_t` has `modificationdate` (a
`time_t`). The bridge currently ignores it and writes `time.Now()`
into `ObjectMeta.ModTime`. Use libmtp's value instead during
enumeration.

**Cost.** ~5 lines in the cgo binding plus the enumeration site.

### 6. Fast-path rename (no copy when source is in MTP, parent unchanged)

**Symptom.** Slow-path rename does a full MTP copy + delete even when
the source file isn't moving across directories. For a 1 GB file
that's ~1 minute of MTP traffic for what should be metadata-only.

**Fix.** MTP's `SetObjectPropValue` lets you change an object's name
in place without re-uploading. Wire this for the case where source
parent == destination parent. Inter-parent renames still require
copy+delete (MTP has no move op).

**Cost.** ~30 lines (new MTP op + dispatch in fs.Rename's slow path).

### 7. CI pipeline upgrades

Per `docs/BUILDING.md` § "CI pipeline: where it bit us, what to do
about it." Specifically: add `workflow_dispatch` trigger + always-
upload `.dmg` as a workflow artifact (option A) plus the smoke-test
launch step (option B). Together: ~20 lines of YAML, catches the
class of regression that broke v0.3.0.

### Out of v0.3.3 scope

- **Multi-storage devices** (phones with SD cards). Real architectural
  work, separate plan.
- **Upstream the go-nfs `unstable` patch.** Separate from Comprador's
  release cadence; do at willscott's pace.
- **Quick Look hazard mitigation.** Carryover from WebDAV findings;
  needs investigation against the NFS path before scoping.

## Order of attack

If picking up incrementally, suggested order:

1. **#1 (phone-side reflection)** — biggest user-perceived gap, well-
   bounded fix.
2. **#7 (CI smoke-test)** — prevents the next class of v0.3.x-style
   broken-ship.
3. **#3 (xattr filter)** — small, visible improvement on the phone.
4. **#5 (mtime mapping)** — small, makes Finder's date-sort useful.
5. **#4 (FSStat refresh)** — small, removes the "X GB available" lie.
6. **#6 (fast-path rename)** — measurable speedup for in-place renames.
7. **#2 (`.local` suffix)** — investigation-heavy; do last.

None of these depend on each other; pick the one with the most
leverage at the moment.
